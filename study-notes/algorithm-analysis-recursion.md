## 풀이 공통 기준

- **정확성:** `base case`, `inductive hypothesis` 또는 `loop invariant`, `inductive step`을 분명히 쓴다.
- **실행 시간:** 입력 크기를 정의하고 worst case를 우선 분석한다. 답은 가능한 한 가장 좁은 big-O 상한으로 쓴다.
- **표기:** \(O(g(n))\)은 실행 시간이 충분히 큰 \(n\)에서 상수배 \(g(n)\)을 넘지 않는다는 상한이다. 이 노트에서는 시간복잡도의 최종 답을 big-O로 통일한다. tight한 big-O란 맞는 상한 중 불필요하게 큰 증가 차수를 피한 것이다.
- **알고리즘:** 조건과 반환값을 먼저 확인한 뒤 알고리즘, 정확성, 실행 시간 순으로 정리한다.

# 1. Algorithm Analysis

## A. 정확성 증명

### 1. 자연수의 합 — `induction` (4쪽)

**조건·규칙:** \(n\)은 양의 정수다. `induction`에서 \(n=1\)을 `base case`로 확인하고, \(k-1\)에서 성립한다고 가정해 \(k\)에서 증명한다.

**문제:** 모든 \(n\ge1\)에 대해 \(\sum_{i=1}^{n}i=n(n+1)/2\)임을 증명하라.

**풀이:** \(n=1\)이면 양변이 1이다. \(k>1\)에 대해 \(\sum_{i=1}^{k-1}i=(k-1)k/2\)라고 가정하자. 그러면

\[
\sum_{i=1}^{k}i=\sum_{i=1}^{k-1}i+k
=\frac{(k-1)k}{2}+k
=\frac{k(k+1)}2.
\]

따라서 `base case`와 `inductive step`에 의해 모든 양의 정수 \(n\)에서 성립한다.

### 2. \(\sqrt2\)의 무리성 — `contradiction` (5쪽)

**조건·규칙:** `contradiction`에서는 명제의 부정을 가정한 뒤 모순을 이끌어낸다. 유리수는 서로소 정수 \(p,q;(q\ne0)\)의 비로 쓸 수 있다.

**문제:** \(\sqrt2\)가 무리수임을 증명하라.

**풀이:** 반대로 \(\sqrt2=p/q\)이며 \(p,q\)가 서로소라고 가정하자. 제곱하면 \(p^2=2q^2\)이므로 \(p^2\)는 짝수다. 홀수의 제곱은 홀수이므로 \(p\)도 짝수이고, \(p=2r\)로 쓸 수 있다. 이를 대입하면 \(4r^2=2q^2\), 즉 \(q^2=2r^2\)여서 \(q\)도 짝수다. \(p,q\)가 모두 2로 나누어져 서로소라는 가정과 모순이다. 따라서 \(\sqrt2\)는 무리수다.

## B. `running time`과 `asymptotic notation`

### 3. 두 알고리즘의 상한 비교 (8쪽)

**조건·규칙:** 입력 크기는 \(n>0\)이다. A의 연산 수는 **최대** \(100n\), B는 **최대** \(3n^2\)이다. 두 값은 실제 연산 수가 아니라 `worst-case upper bound`다.

**문제:** 입력 크기에 따라 어느 알고리즘이 더 유리한지 비교하라.

**풀이:** 제시된 상한끼리 비교하면 \(3n^2<100n\)은 \(0<n<100/3\)에서, \(100n<3n^2\)은 \(n>100/3\)에서 성립한다. 따라서 정수 \(n\le33\)에서는 B의 **제시된 상한**이 작고, \(n\ge34\)에서는 A의 상한이 작다. 점근적으로 A는 \(O(n)\), B는 \(O(n^2)\)이므로 큰 입력에서 A의 상한이 더 느리게 증가한다. 다만 `at most`만 주어졌으므로 실제 입력에서 항상 어느 쪽이 빠른지는 확정할 수 없다.

### 4. 다항식의 \(O(n^3)\) 증명 (11쪽)

**조건·규칙:** \(n\ge1\), \(f(n)=3n^3-n^2+10n+100\). `big-O`를 증명할 때는 \(n\ge n_0\)에서 \(f(n)\le c g(n)\)인 상수 \(c,n_0\)를 찾는다.

**문제:** \(f(n)=O(n^3)\)인지 확인하라.

**풀이:** \(n\ge1\)이면 \(-n^2\le0\), \(n\le n^3\), \(1\le n^3\)이므로
\[
f(n)\le3n^3+10n^3+100n^3=113n^3.
\]
예를 들어 \(c=113,n_0=1\)이 가능하므로 \(f(n)=O(n^3)\)다. 최고차항 \(3n^3\)이 남으므로 \(O(n^{100})\)보다 \(O(n^3)\)가 더 tight한 big-O다.

### 5. 같은 다항식의 \(O(n^{100})\) 증명 (11쪽)

**조건·규칙:** 4번과 같은 \(f(n)\), \(n\ge1\)이다.

**문제:** \(f(n)=O(n^{100})\)인지 확인하고 4번과 비교하라.

**풀이:** \(n\ge1\)에서 \(n^3\le n^{100}\)이므로 4번의 결과를 이용해 \(f(n)\le113n^3\le113n^{100}\)을 얻는다. 따라서 참이다. 그러나 \(O(n^{100})\)은 느슨한 상한이다. 이 함수에 대해 사용할 가장 tight한 big-O는 \(O(n^3)\)다.

### 6. 상수 계수 무시 (12쪽)

**조건·규칙:** 고정된 양의 상수는 점근적 증가 차수를 바꾸지 않는다.

**문제:** \(100n^3=O(n^3)\)인지 확인하라.

**풀이:** \(100n^3\le100n^3\)이므로 \(c=100\)을 택하면 된다. 상수 100은 입력 크기에 따라 커지지 않으므로 가장 tight한 big-O도 \(O(n^3)\)다.

### 7. 합의 규칙 (12쪽)

**조건·규칙:** \(n\ge1\). `sum rule`에서는 가장 빠르게 증가하는 항이 상한을 결정한다.

**문제:** \(n^2+3n=O(n^2)\)인지 확인하라.

**풀이:** \(n\ge1\)이면 \(3n\le3n^2\)이므로 \(n^2+3n\le4n^2\)이다. 가장 빠르게 증가하는 항은 \(n^2\)이므로 가장 tight한 big-O는 \(O(n^2)\)다.

### 8. 곱의 규칙 (12쪽)

**조건·규칙:** \((n^2+3n)(n-10)\)은 \(n\ge10\)에서 음수가 아니다. `big-O`는 충분히 큰 \(n\)만 보면 된다.

**문제:** \((n^2+3n)(n-10)=O(n^3)\)인지 확인하라.

**풀이:** \(n\ge10\)에서 \(n^2+3n\le4n^2\), \(n-10\le n\)이므로 곱은 \(4n^3\) 이하이다. 곱을 전개해도 최고차항이 \(n^3\)으로 남으므로 가장 tight한 big-O는 \(O(n^3)\)다.

### 9. 다항식의 지배항 (13쪽)

**조건·규칙:** \(n\ge1\). 최고차항의 계수는 양수다.

**문제:** \(3n^2+2n+1\)의 가장 tight한 big-O를 구하라.

**풀이:** \(n\ge1\)에서 \(3n^2\le3n^2+2n+1\le6n^2\)이다. 가장 빠르게 증가하는 항이 \(n^2\)이므로 가장 tight한 big-O는 슬라이드와 같이 \(O(n^2)\)다.

### 10. 지수항과 다항항 (13쪽)

**조건·규칙:** \(n\to\infty\)에서 고정된 차수의 다항식보다 밑이 1보다 큰 지수함수가 빠르게 증가한다.

**문제:** \(0.01\cdot2^n+200n^{100}\)의 가장 tight한 big-O를 구하라.

**풀이:** \(n^{100}/2^n\to0\)이므로 충분히 큰 \(n\)에서는 \(200n^{100}\le C2^n\)인 상수 \(C\)가 있다. 다항항은 결국 \(2^n\)보다 느리게 증가하고 \(0.01\cdot2^n\) 항이 남으므로 가장 tight한 big-O는 \(O(2^n)\)이다.

### 11. 작은 밑의 지수함수와 큰 차수의 다항식 (15쪽)

**조건·규칙:** 밑 \(1.000000001\)은 1보다 크고, \(10000000\)은 고정된 상수다. 비교는 모든 작은 \(n\)이 아닌 충분히 큰 \(n\)에 대한 것이다.

**문제:** \(1.000000001^n\)과 \(n^{10000000}\) 중 점근적으로 더 빠르게 증가하는 함수를 고르라.

**풀이:** 양변에 로그를 취하면 \(n\log(1.000000001)\)과 \(10000000\log n\)을 비교한다. \(n/\log n\to\infty\)이므로 결국 앞의 값이 더 크다. 따라서 충분히 큰 \(n\)에서는 \(1.000000001^n>n^{10000000}\)이다. 즉, \(n^{10000000}=O(1.000000001^n)\)이다.

### 12. 작은 차수의 다항식과 큰 거듭제곱의 로그 (15쪽)

**조건·규칙:** \(\log^{1000000}n=(\log n)^{1000000}\)이며, 로그의 밑은 고정된 1보다 큰 수다.

**문제:** \(n^{0.00000001}\)과 \((\log n)^{1000000}\) 중 점근적으로 더 빠르게 증가하는 함수를 고르라.

**풀이:** 임의의 고정된 \(\varepsilon>0\), 정수 \(k>0\)에 대해 \((\log n)^k=o(n^\varepsilon)\)이다. 여기서 \(\varepsilon=0.00000001\), \(k=1000000\)을 대입하면 \(n^{0.00000001}\)이 결국 더 크다. 즉, \((\log n)^{1000000}=O(n^{0.00000001})\)이다.

### 13. 다항 차수와 로그 차수의 비교 (15쪽)

**조건·규칙:** 두 함수는 \(n^3\log n\), \(n(\log n)^5\)이다. 충분히 큰 \(n\)에서 비교한다.

**문제:** 둘 중 어느 함수가 더 빠르게 증가하는지 확인하라.

**풀이:** 첫 함수를 둘째 함수로 나누면 \(n^2/(\log n)^4\)이고, 이는 무한대로 간다. 따라서 \(n^3\log n\)이 점근적으로 더 빠르게 증가한다. 즉, \(n(\log n)^5=O(n^3\log n)\)이다.

## C. 알고리즘 종합 분석

### 14. `insertion sort` (19쪽)

**조건·규칙:** 길이 \(n\ge1\)인 정수 배열 \(L[1..n]\)을 입력받는다. 비교와 인접 원소 교환이 가능하다. 결과는 원래 원소들을 오름차순으로 배열해야 한다.

**문제:** `insertion sort`를 설명하고, `induction`으로 정확성을 증명하며, `worst-case running time`을 구하라.

**Pseudocode:**

```text
procedure InsertionSort(L[1..n])
    for i <- 2 to n do
        j <- i
        while j > 1 and L[j - 1] > L[j] do
            swap L[j - 1] and L[j]
            j <- j - 1
        end while
    end for
end procedure
```

**정확성:** `loop invariant`는 \(i\)번째 반복이 끝나면 \(L[1..i]\)가 정렬되어 있다는 것이다. `base case`인 \(L[1]\)은 원소가 하나라 정렬되어 있다. \(L[1..i-1]\)이 정렬되어 있다고 가정하면, `while`은 \(L[i]\)를 왼쪽으로 이동시키되 자기보다 큰 원소만 지나친다. 끝나면 \(L[1..i]\)가 정렬되고 교환만 했으므로 원소도 보존된다. `induction`에 의해 종료 시 전체 배열이 정렬된다.

**실행 시간 (tight big-O):** worst case는 \(O(n^2)\), 이미 정렬된 배열은 \(O(n)\)이다. 추가 공간은 \(O(1)\)이다.

**이해:** 바깥 반복은 \(i=2,\ldots,n\)까지 진행한다. \(i\)번째에는 새 원소가 최대 \(i-1\)칸 왼쪽으로 이동하므로 전체 비교·교환 수의 상한은 \(1+2+\cdots+(n-1)=n(n-1)/2\)이다. 이 합에서 가장 크게 증가하는 항이 \(n^2\)이므로 \(O(n^2)\)다. 역순 배열에서는 실제로 이만큼 이동한다. 정렬된 배열은 매번 while 조건만 확인하고 넘어간다. Master Theorem은 재귀가 없으므로 사용하지 않는다.

# 2. Recursion

## A. `self-reduction`

### 15. `Hanoi Tower` (4–7쪽)

**조건·규칙:** \(n>0\)개의 크기가 다른 원판이 첫 기둥에 작은 것부터 위에 쌓여 있다. 한 번에 원판 하나만 옮길 수 있고, 큰 원판을 작은 원판 위에 둘 수 없다. 세 번째 기둥으로 모두 옮기는 유효한 이동 순서를 구한다.

**문제:** 세 기둥 `start`, `mid`, `dest`를 사용한 재귀 알고리즘을 작성하고 정확성과 실행 시간을 분석하라.

**Base case:** 원판이 \(n=1\)개면 \(start\)에서 \(dest\)로 한 번 옮긴다.

**Recurrence relation:** \(n>1\)이면 위의 \(n-1\)개를 \(mid\)로 옮기고, 가장 큰 원판을 \(dest\)로 옮긴 뒤, \(n-1\)개를 \(mid\)에서 \(dest\)로 옮긴다. 즉, 더 작은 Hanoi 문제를 두 번 푼다.

**Pseudocode:**

```text
procedure Hanoi(n, start, mid, dest)
    if n = 1 then
        Move plate 1 from start to dest
    else
        Hanoi(n - 1, start, dest, mid)
        Move plate n from start to dest
        Hanoi(n - 1, mid, start, dest)
    end if
end procedure
```

**정확성:** \(n=1\)이면 한 번의 이동이 유효하다. \(n-1\)개에 대해 옳다고 가정하자. 첫 재귀 호출이 위의 \(n-1\)개를 `mid`로 옮기므로 가장 큰 원판을 빈 `dest`로 옮길 수 있다. 둘째 재귀 호출은 그 \(n-1\)개를 가장 큰 원판 위로 옮기며 규칙을 어기지 않는다. 따라서 `induction`으로 모든 \(n>0\)에서 유효하다.

**실행 시간 (tight big-O):** \(T(1)=O(1)\), \(T(n)=2T(n-1)+O(1)\)이고 답은 \(O(2^n)\)이다. 재귀 깊이에 따른 공간은 \(O(n)\)이다.

**이해:** 원판 \(n\)개를 옮기려면 \(n-1\)개 문제를 두 번 풀고 가장 큰 원판을 한 번 옮긴다. 이동 횟수를 \(M(n)\)이라 두면 \(M(1)=1\), \(M(n)=2M(n-1)+1\)이므로 \(M(n)=2^n-1\)이다. 따라서 \(2^n\) 상한은 불필요하게 큰 차수가 아니다. 문제 크기가 \(n-1\)로 줄어들며 \(n/b\) 형태가 아니어서 Master Theorem은 적용하지 않는다.

## B. `divide and conquer`

### 16. `merge phase` (11–13쪽)

**조건·규칙:** 두 배열 \(A[1..n_1]\), \(B[1..n_2]\)는 각각 오름차순으로 정렬되어 있다. 중복 값이 있을 수 있다. 두 배열의 모든 원소를 보존하면서 오름차순 배열 \(C\)를 만든다.

**문제:** 두 정렬 배열을 합치는 알고리즘을 작성하고, 강의 자료처럼 \(i+j\)에 대한 induction으로 정확성을 증명하며 시간을 구하라.

**구분:** merge phase는 17번 merge sort의 세 번째 단계다. 강의 자료는 병합 중 선택한 원소의 순위를 \(i+j\)에 대한 induction으로 증명한다.

**Pseudocode:**

```text
procedure Merge(A[1..n1], B[1..n2])
    create C[1..n1+n2]
    i <- 1; j <- 1

    while i <= n1 and j <= n2 do
        if A[i] < B[j] then
            C[i + j - 1] <- A[i]
            i <- i + 1
        else
            C[i + j - 1] <- B[j]
            j <- j + 1
        end if
    end while

    while i <= n1 do
        C[i + j - 1] <- A[i]
        i <- i + 1
    end while
    while j <= n2 do
        C[i + j - 1] <- B[j]
        j <- j + 1
    end while
    return C
end procedure
```

**정확성 — \(i+j\)에 대한 induction:**

- **Claim:** main loop에서 \(A[i]\)와 \(B[j]\)를 비교할 때, 둘 중 작은 값은 두 입력 배열 전체에서 \((i+j-1)\)번째로 작은 값이며 결과 배열 \(C[i+j-1]\)에 저장된다.
- **Base case:** \(i=j=1\)이면 \(i+j-1=1\)이다. 정렬된 \(A\)와 \(B\)의 첫 원소 \(A[1]\), \(B[1]\) 중 작은 값이 전체의 최솟값이므로 \(C[1]\)에 올바르게 들어간다.
- **Inductive hypothesis:** \(i+j-1>1\)일 때, 앞서 선택한 \(i+j-2\)개의 값이 \(A[1..i-1]\)과 \(B[1..j-1]\)에서 나왔고 전체의 작은 값부터 순서대로 \(C[1..i+j-2]\)에 들어갔다고 가정한다.
- **Inductive step:** 남은 부분 \(A[i..n_1]\), \(B[j..n_2]\)는 각각 정렬되어 있다. 따라서 \(A[i]\)와 \(B[j]\) 중 작은 값이 아직 남은 원소 전체의 최솟값이다. 앞의 \(i+j-2\)개를 이미 골랐으므로 이 값은 전체의 \((i+j-1)\)번째로 작은 값이고 \(C[i+j-1]\)에 들어간다.
- **main loop 종료 후:** 한 배열이 모두 소진되면 다른 배열에 남은 값들은 이미 선택한 값보다 크거나 같고 정렬되어 있다. 남은 값을 차례로 복사하면 \(C\) 전체가 정렬되며 모든 원소가 보존된다. 한 입력 배열이 처음부터 비어 있어도 같은 방식으로 다른 배열을 복사한다.

**실행 시간 (tight big-O):** \(O(n_1+n_2)\)이다. 출력 배열은 \(O(n_1+n_2)\) 공간을 쓴다.

**이해:** while의 한 번 반복마다 두 입력 배열 중 하나에서 원소 하나를 출력 배열로 옮긴다. 남은 원소를 복사할 때도 각 원소를 한 번씩만 옮긴다. 따라서 총 \(n_1+n_2\)개 원소에 대해 상수 시간 작업을 하므로 \(O(n_1+n_2)\)다. 결과 배열의 모든 칸을 채워야 하므로 더 낮은 차수의 big-O로 줄일 수 없다. 재귀가 없으므로 Master Theorem은 사용하지 않는다.

### 17. `merge sort` (10–14쪽)

**조건·규칙:** 길이 \(n\ge1\)인 정수 배열을 오름차순으로 정렬한다. 두 부분 배열의 크기는 \(\lfloor n/2\rfloor\), \(\lceil n/2\rceil\)로 둘 수 있다.

**문제:** `divide and conquer`로 정렬하고, `merge phase`의 정확성을 이용해 전체 알고리즘을 증명하며 시간을 구하라.

**Base case:** 강의 자료처럼 \(n=1\)이면 원소가 하나여서 이미 정렬되어 있으므로 그대로 반환한다.

**Recurrence relation:** \(n>1\)이면 다음 세 단계를 순서대로 수행한다.

**강의 슬라이드의 알고리즘 단계:**

1. **Divide:** 입력 배열을 크기가 각각 \(\lfloor n/2\rfloor\), \(\lceil n/2\rceil\)인 두 부분 배열로 나눈다.
2. **Recursively merge sort:** 두 부분 배열을 각각 merge sort로 정렬한다.
3. **Merge:** 정렬된 두 부분 배열을 하나의 정렬된 배열로 합친다. 이 작업의 세부 방법이 16번 merge phase다.

**Pseudocode:**

```text
procedure MergeSort(L)
    if length(L) = 1 then
        return L
    end if
    m <- floor(length(L) / 2)
    left <- MergeSort(L[1..m])
    right <- MergeSort(L[m+1..length(L)])
    return Merge(left, right)
end procedure
```

**정확성 — \(n\)에 대한 induction:**

- **Base case:** \(n=1\)이면 원소가 하나뿐이므로 배열은 이미 정렬되어 있다.
- **Recurrence relation:** 크기가 \(n\)보다 작은 배열은 MergeSort가 올바르게 정렬한다고 가정한다. 그러면 두 재귀 호출이 각각의 부분 배열을 정렬한다. 16번에서 증명한 merge phase는 이 두 정렬 배열의 모든 원소를 보존하면서 하나의 정렬 배열로 합친다. 따라서 크기 \(n\)의 배열도 올바르게 정렬된다.
- **결론:** base case와 recurrence relation이 성립하므로 induction에 의해 모든 \(n\ge1\)에 대해 MergeSort가 정확하다.

**실행 시간 (tight big-O):**

- **Base case:** \(n=1\)이면 정렬할 작업이 없으므로 \(T(1)=O(1)\)이다.
- **Recurrence relation:** 크기 \(n/2\)의 부분 배열을 두 번 정렬하고, merge phase에 \(f(n)=O(n)\)이 든다. 따라서 \(T(n)=2T(n/2)+f(n)\)이다.

**점화식 전개:** 강의 자료처럼 \(n\)을 2의 거듭제곱이라고 두자. merge phase의 비용이 \(f(n)\le cn\)인 상수 \(c\)가 있으므로,

\[
\begin{aligned}
T(n)&\le 2T(n/2)+cn\\
&\le 4T(n/4)+2cn\\
&\le 8T(n/8)+3cn\\
&\ \vdots\\
&\le nT(1)+cn\log_2 n\\
&=O(n\log n).
\end{aligned}
\]

**이해:** 분할할 때마다 부분 배열의 크기가 절반이 되므로 \(n\to n/2\to n/4\to\cdots\to1\)까지 약 \(\log_2 n\)단계가 걸린다. 각 단계의 모든 merge 작업을 합하면 원소 \(n\)개를 한 번씩 다루는 \(O(n)\)이다. 따라서 총 \(O(n\log n)\)이다. 홀수 길이에서 \(\lfloor n/2\rfloor\), \(\lceil n/2\rceil\)로 나누어도 같은 big-O가 나온다. 보조 배열은 \(O(n)\) 공간을 쓴다.

**Master Theorem:** \(a=2,\ b=2,\ f(n)\)은 \(n\)에 비례한다. 기준값은 \(\log_b a=\log_2 2=1\)이고 \(f(n)\)의 \(n\) 차수도 1이므로 강의 자료의 case 2(\(k=0\))에 해당한다. 따라서 \(T(n)=O(n^{\log_2 2}\log n)=O(n\log n)\)이다.

### 18. `binary search` (15–16쪽)

**조건·규칙:** \(L[1..n]\)은 정렬된 정수 배열이며 \(n\ge0\)이다. 질의 정수 \(q\)가 배열에 있으면 True, 없으면 False를 반환한다. 재귀에 넘기는 부분 배열은 복사하지 않고 원래 배열의 구간을 가리키는 view로 취급하며, 각 호출에서는 그 부분 배열의 인덱스를 다시 1부터 센다.

**문제:** 가운데 원소를 이용한 재귀 탐색을 작성하고 정확성과 실행 시간을 분석하라.

**Base case:** 배열 길이 \(n=0\)이면 False, \(n=1\)이면 유일한 원소를 \(q\)와 비교해 결과를 반환한다. \(n>1\)에서 가운데 원소가 \(q\)와 같아도 바로 True를 반환한다.

**Recurrence relation:** \(q<L[m]\)이면 \(L[1..m-1]\), \(q>L[m]\)이면 \(L[m+1..n]\)에서 같은 문제를 다시 푼다. 여기서 \(m=\lceil n/2\rceil\)이다.

**ceil과 base case:** ceil 함수는 값을 올림한다. 예를 들어 \(\lceil 5/2\rceil=3\), \(\lceil 2/2\rceil=1\)이다. \(n=2\)일 때 \(m=1\)이어도 현재 배열의 길이는 2이므로 \(n=1\)인 base case에 해당하지 않는다. 가운데 원소와 비교한 뒤 필요한 경우 길이가 0 또는 1인 부분 배열로 재귀 호출하고, 그다음 호출에서 base case를 처리한다.

**슬라이드 표기 주의:** \(L[m]<q\)는 가운데 원소가 \(q\)보다 작은 경우이므로 오른쪽 범위 \(L[m+1..n]\)을 탐색한다. 슬라이드의 오른쪽 끝 \(n-1\)은 마지막 원소 \(L[n]\)을 빠뜨린 표기 오류다. 반대로 \(q<L[m]\)이면 왼쪽 범위 \(L[1..m-1]\)을 탐색한다.

**Pseudocode:**

```text
procedure BinarySearch(L[1..n], q)
    if n = 0 then
        return False
    end if
    if n = 1 then
        return (L[1] = q)
    end if

    m <- ceil(n / 2)
    if L[m] = q then
        return True
    else if L[m] > q then
        return BinarySearch(L[1..m-1], q)
    else
        return BinarySearch(L[m+1..n], q)
    end if
end procedure
```

**정확성:** \(n=0\)이면 찾을 원소가 없고, \(n=1\)이면 유일한 원소를 직접 비교하므로 결과가 맞다. \(n>1\)에서 가운데 값이 \(q\)면 True가 맞다. \(q<L[m]\)이면 정렬 조건 때문에 \(m\) 이후에는 \(q\)가 없고, \(q>L[m]\)이면 \(m\) 이전에는 없다. 따라서 답이 있을 수 있는 절반만 재귀 탐색해도 답이 보존된다.

**실행 시간 (tight big-O):** worst case는 \(O(\log n)\), 처음 가운데 원소가 답인 경우는 \(O(1)\)이다. 재귀 호출 공간은 \(O(\log n)\)이다.

**이해:** 매 호출에서 가운데 값을 한 번 비교하고, 답이 없으면 후보 범위를 절반으로 줄인다. \(n\to n/2\to n/4\to\cdots\to1\)이 되기까지 약 \(\log_2 n\)번의 호출이 필요하므로 \(T(n)=T(n/2)+O(1)=O(\log n)\)이다. 부분 배열을 실제로 복사하면 복사 비용이 생기므로, 이 분석에서는 view 또는 인덱스 범위를 사용한다.

**Master Theorem:** \(a=1,\ b=2\)이고 각 호출의 비교 작업 \(f(n)\)은 일정한 상수 시간이므로 \(O(1)\)이다. \(\log_b a=\log_2 1=0\)이고 호출당 작업도 \(n^0\) 수준이므로 case 2(\(k=0\))를 적용해 \(T(n)=O(n^0\log n)=O(\log n)\)을 얻는다.

## C. `backtracking`

### 19. `N-queens` (21–23쪽)

**조건·규칙:** \(n>0\)인 \(n\times n\) 보드에 queen \(n\)개를 놓는다. 같은 행, 열, 대각선에 둘 수 없다. 각 행에 정확히 하나씩 놓으며 \(Q[r]\)을 \(r\)번째 행의 열 번호로 둔다.

**문제:** 모든 유효한 배치의 **개수**를 반환하는 `backtracking` 알고리즘을 작성하고 정확성과 실행 시간을 분석하라. 8-queens는 \(n=8\)인 사례다.

**Base case:** \(r=n\)이면 유효한 배치 하나를 완성했으므로 1을 반환한다.

**Recurrence relation:** 다음 행의 각 열 \(i\)를 시험한다. 기존 queen과 충돌하지 않으면 \(Q[r+1]=i\)로 놓고, 남은 행의 경우의 수를 재귀적으로 구해 모두 더한다.

**Pseudocode:**

```text
procedure NQueens(Q[1..n], r)
    if r = n then
        return 1
    else
        num <- 0
        for i <- 1 to n do
            flag <- True
            for j <- 1 to r do
                if Q[j] = i or Q[j] = i + (r + 1 - j)
                   or Q[j] = i - (r + 1 - j) then
                    flag <- False
                end if
            end for
            if flag then
                Q[r + 1] <- i
                num <- num + NQueens(Q, r + 1)
            end if
        end for
        return num
    end if
end procedure

Call NQueens(Q, 0)
```

**정확성:** \(r\)개의 queen이 놓인 모든 재귀 상태는 서로 공격하지 않는 배치다. 새 queen을 현재 행의 모든 열에 시험하고, 같은 열이나 대각선에 있는 경우만 제외하므로 유효한 확장만 재귀한다. 완성된 배치는 행마다 열 번호가 하나씩 정해져 정확히 한 경로로 도달한다. 완성된 유효 배치마다 1을 반환해 합치므로 누락이나 중복 없이 개수를 센다.

**실행 시간 (big-O):** 강의 자료의 답은 \(O(n!)\)이다. 이는 열이 중복되지 않는 배치 후보가 최대 \(n(n-1)\cdots1=n!\)개라는 설명이다. 위 수도 코드의 충돌 검사까지 기본 연산으로 세면 안전한 상한은 \(O(n^2n!)\)이다. 재귀 깊이와 \(Q\) 배열 공간은 \(O(n)\)이다. \(n=8\)일 때 답은 92개다.

**이해:** 첫 행은 최대 \(n\)개 열, 다음 행은 이미 쓴 열을 제외하면 최대 \(n-1\)개 열, 그다음은 최대 \(n-2\)개 열을 시도할 수 있어 후보 수에 factorial이 나타난다. 대각선 조건은 일부 후보를 일찍 제거한다. 다만 수도 코드는 각 재귀 상태에서 \(n\)개 열을 순회하고 열마다 앞선 queen을 최대 \(n\)개 검사하므로, 강의의 \(O(n!)\)은 검사 비용을 생략한 값이다. 분기 수가 깊이에 따라 바뀌고 하위 문제가 \(n/b\) 크기로 나뉘지 않아 Master Theorem은 적용하지 않는다.

### 20. `subset sum` (24–25쪽)

**조건·규칙:** \(X\)는 \(n\)개의 **양의 정수**로 이루어진 집합이고, \(t\)는 목표 정수다. 원소마다 선택하거나 선택하지 않는 두 경우를 고려한다. 양의 정수만 있으므로 남은 목표 \(t<0\)이면 그 경로는 중단해도 된다.

**문제:** 합이 정확히 \(t\)인 부분집합의 존재 여부를 반환하는 `backtracking` 알고리즘을 작성하고 정확성과 실행 시간을 분석하라. 자료의 사례는 \(X=\{1,2,3,5,7,9\},t=20\)과 \(X=\{2,3,5,7,9\},t=20\)이다.

**Base case:** 남은 목표 \(target=0\)이면 True다. \(target<0\)이거나 원소를 다 보았는데 \(target>0\)이면 False다.

**Recurrence relation:** 현재 원소 \(x\)를 제외한 문제 \((X\setminus\{x\},target)\)와 포함한 문제 \((X\setminus\{x\},target-x)\)를 풀고, 두 결과 중 하나라도 True이면 True다.

**Pseudocode:**

```text
procedure SubsetSum(X[1..n], index, target)
    if target = 0 then
        return True
    end if
    if target < 0 or index > n then
        return False
    end if

    return SubsetSum(X, index + 1, target)
        or SubsetSum(X, index + 1, target - X[index])
end procedure

Call SubsetSum(X, 1, t)
```

**정확성:** `target=0`이면 지금까지 선택한 원소가 목표 합을 만들었다. `target<0`이면 남은 양의 정수를 더해 0으로 되돌릴 수 없고, 원소가 없는데 `target>0`이면 만들 수 없다. 그 외에는 현재 원소를 제외한 부분집합과 포함한 부분집합으로 모든 가능성이 정확히 나뉜다. 두 재귀 결과의 논리합이 전체 문제의 답이다.

**실행 시간 (tight big-O):** \(T(n)=2T(n-1)+O(1)\)에서 worst case는 \(O(2^n)\)이다. 재귀 깊이에 따른 공간은 \(O(n)\)이다. 첫 사례는 \(\{1,3,7,9\}\)의 합이 20이라 True, 둘째 사례는 해당 부분집합이 없어 False다.

**이해:** 원소 하나마다 선택하지 않음·선택함의 두 갈래가 생긴다. 가지치기가 전혀 없다면 깊이 0,1,2,\ldots,n의 노드 수는 \(1,2,4,\ldots,2^n\)이므로 전체는 \(1+2+\cdots+2^n=O(2^n)\)이다. 예를 들어 \(t\)가 모든 원소의 합보다 크면 어느 경로도 일찍 성공하거나 음수가 되지 않아 모든 분기를 검사한다. 따라서 이 big-O는 불필요하게 큰 상한이 아니다. 문제 크기가 \(n-1\)로 줄어들기 때문에 Master Theorem은 적용하지 않는다.

## 슬라이드의 개념·표기 확인

- `worst case`, `best case`, `average case`는 서로 다른 입력 기준이다. 6–7쪽의 정렬 사례는 이 차이를 설명하는 예시로, 별도 알고리즘 문제로 세지 않았다.
- \(O(1), O(\log n), O(n), O(n\log n), O(n^2), O(n^3), O(c^n), O(n!)\)는 14쪽의 대표 성장 순서다. \(0.1^n=O(1)\), \(n!=O(n^n)\)도 14–15쪽의 확인 예시다.
- Master Theorem은 \(T(n)=aT(n/b)+f(n)\) 형태에 사용한다. 이 자료에서는 merge sort와 binary search에 적용하며, 각각의 문제에 \(a,b,f(n)\)과 해당 case를 적었다.
- 11쪽 merge phase에는 배열 경계 표기가 혼재한다. 16번 풀이에서는 1-based index에 맞춰 \(\le\) 경계를 일관되게 사용했다. 15–16쪽 binary search의 재귀 구간도 1-based index로 다시 썼다. 22쪽 N-queens의 대각선 비교는 새 queen의 행이 \(r+1\)이라는 점을 반영했다.
- 23쪽 N-queens의 \(O(n!)\)는 배치 후보 수 중심의 분석이다. 수도 코드의 충돌 검사 비용까지 세면 19번에 적은 별도 상한을 사용한다.
